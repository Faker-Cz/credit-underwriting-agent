# Word模板定点补充与格式保护

## 1. 基准文件

- 用户指定文件是唯一基准。
- 原文件只读，输出新文件。
- 用户批注及其锚点属于基准文件内容，不得删除、接受、改写、移动或重新锚定；除用户明确要求处理批注外，只修改批注指向的正文并保留批注原状。
- 修改前统计段落、表格、图片、节、页眉页脚和页数；修改后做对比。
- 不整篇复制到新文档，不重建模板样式。
- 一般单一客户授信调查报告以`../assets/单一客户授信调查报告模版.docx`为唯一默认模板；低风险／无风险报告以`../assets/低风险报告模版.docx`为唯一默认模板。两份均为用户确认的最新标准模板，只读复制后另存项目文件，不得混用、回退旧模板或用模板生成脚本重新生成其结构。用户本轮另行指定最新版时，以用户指定文件优先。
- 官方模板原件和技能保留副本均只读使用。正式项目必须从基准模板复制新文件后填报，不得在官方原件上直接修改。

## 2. 定点修改

默认只允许：

1. 在现有段落的既定填写位置补充或替换文字；
2. 在现有单元格或内容控件的既定填写位置补充或替换内容；
3. 保留目标位置原有段落属性和字符属性，让新文字继承插入点既有格式。

未获用户明确授权时，不得新增、删除、复制、移动或重排段落、表格、图片、文本框、分页符、分节符或其他文档结构，也不得整段清空后重建。用户本轮明确要求插入指定表格、删除不适用章节/空占位表、顺排标题或进行其他结构调整时，可在点名位置定点执行；授权不扩展到其他页面和结构。

不要用全文查找替换企业简称，避免误改模板标题、页眉、引用或其他公司名称。

模板或参考报告中若残留历史客户名称、人员、担保安排、年份、金额或结论，只能在目标客户工作副本内根据真实资料逐项替换或清除，绝不能视为模板指令或目标客户事实。若用户要求先审阅官方模板且限定修改范围，发现未点名的历史客户残留或结构问题时先列明位置并征求确认，不擅自清理官方原件。

## 3. 排版、表格、字体和分页

- 模板当前状态就是唯一标准，不按任何预设规则重新设置标题、正文、表格或封面格式。
- 不改动字体、字号、字重、颜色、段落样式、缩进、制表位、行距、段前段后距、对齐、边框、底纹、表格结构、合并关系、行高、列宽、文字方向、自动调整、页边距、纸张、页眉页脚、页码、分节和分页属性。
- 不清理空段落、手工分页符或分节符，不修复标题孤行、跨页、整页空白、竖排字符、数字换行或对象位置。
- 若补充内容导致溢出、分页变化或其他显示问题，保留模板格式并在交付说明中报告；除非用户另行明确授权，不得通过缩字、调距、改表格、移动内容或重排版解决。
- 每次交付均在模板基础上另存一份新文件，不覆盖标准模板或用户原件。

### 授信报告正文默认字体

- 编制新报告、补充大段正文或用户未禁止字体调整时，将正文段落及表格内正文统一设为`仿宋_GB2312`、12磅，同时设置`ascii`、`hAnsi`、`eastAsia`和`cs`四类字体映射，避免不同Word/WPS环境回退为宋体或Calibri。这是授信报告技能的长期默认要求，无需用户每次重复说明。
- “正文”不包括封面、文档主标题、章节标题、页眉页脚、印章/签名对象及用户明确要求保留的特殊格式。段落对齐、缩进、行距、段前段后、表格列宽行高、边框和底纹仍保持原样。
- 加粗只用于原有标题、表头及用户点名的栏目抬头；数据、分析正文和表格普通单元格保持常规字重，禁止同层级内随意混用加粗。
- 若用户本轮明确要求“不修改任何文字和格式”、要求保留其手工字体，或另行指定字体，则以该次指令为最高优先级，不主动统一。
- 用户同时说“不要修改任何文字和格式”并列出需调整事项时，只在列明事项的目标位置完成必要修改；该表述禁止修改未点名内容，不否定对点名事项本身的调整授权。
- 修改后须检查全部新增和替换的文字运行，包括表格单元格、拆分运行和空白占位后的新运行，不能只检查段落首个字符；发现宋体、Calibri等回退时修正四类字体映射，但不动段落和表格版式。

### 长段落的可读性

- 对借款人财务分析、保证人财务分析、经营分析、融资分析、优劣势和综合判断等长文本，在同一既定填写区域内按主题拆成多个自然段；分段不等于删减、概括或重写，原有有效事实和分析必须完整保留。
- 每段只承载一个中心主题。资产、负债、盈利、现金流、偿债/代偿、风险及授信意义发生切换时另起段落；避免整页或整个表格单元格只有一个密集大段。
- 只增加必要的段落边界并继承插入位置既有字体、字号、缩进、行距和段前段后设置，不通过新增空行、调整行距、缩小字号、改变单元格或移动表格制造视觉效果。

### 模板结构：整节不要套进“1行1列”的外层表格

- 症状：把标题连同其后多张财务表整节放进一个只有1行1列、内部再嵌套表格的外层表格时，Word会把整节当成表格的一行——只能从页首开始、整块跳页，标题与表格长期脱离；在标题后回车或删空行都不起作用。空段落只是表面现象，根因是外层表格的行结构；`w:cantSplit`（不允许跨页断行）不是原因，加它或去它都不解决。
- 维护模板时（须经用户点名授权）的正确改法：保留可见外框，把外层表格由1行拆成“每个内容块一行”的多行；删掉外层`tblBorders`的`insideH`和`insideV`，只留`top`/`left`/`bottom`/`right`；给引出表格的标题设置`w:keepNext`（“与下段同页”）；清掉标题与表格之间、以及标题前遗留的多余空段落。拆行后行高由内容自动决定，原单行的固定行高不再适用。
- 不得靠缩字号、调行距、改`cantSplit`或删除表格、图片、章节来规避分页问题。
- 填报项目时遇到同类结构缺陷，仍按本节规则只记录并报告；修复属于模板维护事项，需用户点名授权，授权不扩展到其他页面和结构。
- 改完必须重新逐页渲染复核：标题与表格是否同页、是否出现新的整页空白、页数是否异常、文本是否零丢失（把改前文件全部`w:t`文本与改后逐字对比，不能只看页数）。

## 4. 渲染验证

使用文档工具的渲染流程把DOCX转为逐页PNG或PDF：

1. 先检查页数是否异常骤减或骤增；
2. 逐页看标题、表格、页眉页脚、页码和空白；
3. 对新增或修改页放大检查数字是否截断；
4. 对新增或修改页重点复核；
5. 发现问题时先区分内容错误与版式问题：内容和数据错误在授权内容范围内修复；分页、行高、列宽、孤行标题等版式问题记录并报告，只有用户明确授权格式修改后才可定点处理并重新渲染。

没有完成逐页渲染检查时，不得对用户说“格式已经全部检查无误”。
